## WHAT I BUILT
Fixed all six items in PROJECT_BRIEF.md's "CLI bugs" backlog:
1. `explain.py::summarize_findings` — `"".splitlines()` returns `[]` not
   `[""]`, so an empty/missing `description` raised `IndexError`. Guarded the
   index.
2. `fix.py::_analyzer_available()` — only checked `shutil.which("slither")`;
   `SlitherAnalyzer.run()` actually falls back to
   `pipx run --spec slither-analyzer slither ...` when slither isn't
   directly on PATH, so a pipx-only environment was reporting `UNVERIFIED`
   unnecessarily. Now also accepts `shutil.which("pipx")`.
3. `fix.py`'s `git apply` (`_run_git_apply`) and `git init` (inside
   `verify_fix`) subprocess calls had no `timeout=`, so either could hang the
   CLI indefinitely. Added `timeout=30` (matching `_compile_with_solc`'s
   existing pattern) to both; both now degrade to a controlled `FAILED`
   verdict instead of hanging or raising uncaught.
4. `aura fix <directory>` crashed with an uncaught `IsADirectoryError` deep
   inside `verify_fix_loop` (`Path.read_text()` on a dir). `fix_cmd` now
   validates `Path(target).is_file()` up front and exits 1 with a clear
   message.
5. `VerifyResult.new_findings` was already populated on `REGRESSED` but never
   surfaced by `fix_cmd` — added to the `--json` payload and to text output
   (rule + severity, one per line).
6. `fix_cmd` never called `typer.Exit`, so every verdict (including
   `FAILED`/`REGRESSED`) exited 0. Now exits 1 on `FAILED`/`REGRESSED` (left
   `VERIFIED`/`UNVERIFIED` at 0 — the backlog note only called out the first
   two).

Added test coverage for every change (new `tests/test_summarize_findings.py`;
new cases in `tests/test_fix.py` and `tests/test_cli.py`) rather than relying
on manual verification alone.
