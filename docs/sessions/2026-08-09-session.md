### Bugs the review loop caught (recorded honestly, not smoothed over)

- **Task 5:** `load_findings` raised `AttributeError` on valid-but-non-dict
  JSON (a list, string, number, or `null`), which broke `run_comment.py`'s
  always-exit-0 guarantee — a malformed findings file would have failed the
  user's build on a docs tool that's supposed to degrade safely. Fixed
  (`d0c6161`) with an `isinstance` check plus `main()`-level tests covering
  malformed JSON, posting failures, and invalid gate thresholds. A follow-up
  round (`ca12209`) also fixed a non-hermetic test that hit the real `gh`
  CLI over the network and wrote a stray `aura-comment.md` into the repo
  root.
- **Task 6 (the significant one):** `aura fix --write --json` prints its
  JSON payload and *then* appends a human-readable line ("Wrote verified fix
  to `<path>`" / "Refusing to write: ..."), so `run_fix`'s `json.loads()`
  raised `json.JSONDecodeError` ("Extra data") on every real invocation.
  Every verdict silently became `ERROR`, `verified()` was always empty, and
  **no fix PR could ever have been opened** — the feature was fail-safe but
  completely non-functional end-to-end. Unit tests missed it because the
  fake runner returned idealized single-object JSON the real CLI never
  produces. Fixed (`54b12f3`) in `action/scripts/fixes.py` with
  `json.JSONDecoder().raw_decode()` to extract the leading JSON object,
  following the same noise-tolerant pattern already used in
  `slither_adapter.py::_extract_json_block`. `src/aura/cli.py` was left
  untouched — changing its stdout shape would break tested output shapes
  per `docs/NEVER_DO.md`. Also caught in the same pass: `subprocess.TimeoutExpired`
  is not an `OSError` subclass, so a slow LLM call hitting the 900s timeout
  would have propagated uncaught out of `run_fixes.py::main()`'s list
  comprehension before any `GITHUB_OUTPUT` was emitted — now caught
  alongside the JSON-parsing fix.
